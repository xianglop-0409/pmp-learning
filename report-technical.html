二、关键复杂问题及解决

问题1：CDN被墙 → 页面无限加载

现象：中国用户打开页面后一直显示"加载中"，无法进入应用。
根因：unpkg.com 和 cdn.jsdelivr.net 在国内DNS污染，Dexie.js、D3.js、Chart.js均无法加载。
解决方案：将三个库通过npm安装后复制到 js/vendor/ 目录，修改 utils.js 的 loadScript 函数优先本地加载，CDN仅作为兜底。

问题2：知识图谱手机端体验

版本实现方式问题
v1可折叠HTML树形菜单只是跳转菜单，没有可视化
v2Canvas手写同心圆布局 + 触摸命中检测点击事件this绑定丢失
v3（最终）闭包引用 + 4层圆环布局 + 进度着色✅ 拖拽/缩放/点击/详情弹窗全部正常
技术要点：用 const self = TreeView 闭包引用解决事件回调的this问题；用 Math.hypot(x - n.x, y - n.y) 做触摸命中检测；Canvas的 devicePixelRatio 缩放保证高清渲染。

问题3：题库数据质量（最耗时）

原始题库2800题存在严重质量问题：106题英文占比超过35%、题目中混入英文句子片段、题干包含"[单选题]分值:1分"垃圾前缀、668题缺答案解析。
解决方案：编写Python清洗脚本，正则匹配删除英文长句（[A-Za-z]{30,}）、清除垃圾前缀、提取泄露在题干中的正确答案后删除、过滤英文过重题目。最终从2800题精简为2694道干净题目。

问题4：多设备同步（迭代最多）

尝试方案遇到问题结果
1Node.js API + serveo双隧道serveo URL频繁变化，隧道断开❌
2手动导出JSON → 百度网盘每换电脑需手动导入❌ 太麻烦
3GitHub Gist APIToken缺少gist权限 → GitHub返回404❌
4（最终）GitHub Gist API（重新生成Token勾选gist）功能正确✅
关键发现：GitHub API在Token权限不足时返回404而非401，极具误导性。
最终方案：手动创建Gist → 系统设置页填入Token和Gist ID → 点击同步 → 先Pull云端合并 → 再Push本地 → 页面刷新。

问题5：PWA Service Worker 缓存顽固

修改JS/CSS文件后用户看到的仍是旧版本，多次刷新无效。
解决方案：在index.html中加入SW注销脚本（getRegistrations().then(regs => regs.forEach(r => r.unregister()))），同时增加HTML引用版本号 js/app.js?v=m5 强制绕过缓存。

四、经验教训

  1. 国内用户不能用海外CDN — 所有关键依赖必须本地化，CDN仅作兜底
  2. GitHub API错误信息不友好 — 404可能是权限不够，不是资源不存在
  3. 手机端可视化不能依赖D3 — Canvas手写虽然麻烦但体验可控
  4. Service Worker是一把双刃剑 — 开发阶段应禁用，上线后才启用
  5. 题库质量是产品生命线 — 2694题清洗投入了大量正则和人工时间，但这是核心价值所在
  6. Hash路由是纯静态应用的最佳选择 — 无需服务器配合，直接文件访问也能路由
