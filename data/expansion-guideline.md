# PMP学习机知识内容扩写规范

本规范用于指导将 `js/knowledge-content.js` 中76个知识节点扩写到 **3000-5000字/节点**。

## 总体要求

1. **字数**：每个节点扩写到 3000-5000 中文字符（overview + details各条目 + keyConcepts + examTips 合计）。
2. **风格**：要点式 + 小标题。使用 `- **术语**：解释` 的要点格式，便于扫读。
3. **准确性**：严格依据 PMBOK 第8版 / 敏捷实践指南 / 过程组实践指南内容，术语使用规范中文（干系人、挣值、冲刺、待办事项列表等）。
4. **ITTO 完整展开**：每个过程的输入、工具与技术、输出必须逐个解释（各配一句"是什么+用途/怎么用"），不得只列名称。
5. **禁止编造**：不虚构不存在的概念；不确定的内容宁缺毋滥。
6. **考试导向**：每个节点必须包含 examTips（考试要点/常见陷阱），突出高频考点。

## 输出格式（JSON 对象，key = 节点id）

每个节点扩写为一个对象，包含字段：`overview`（概述）、`details`（附加区块，嵌套对象，标题带emoji）、`keyConcepts`（关键概念）、`examTips`（考试要点）。

### 各类型节点模板

#### 过程节点（proc-*）
```json
{
  "proc-example": {
    "overview": "【过程概述】过程目的、关键收益、执行频率（要点式，400-600字）",
    "details": {
      "📥 输入 Inputs": "- **输入名**：用途解释\n...（逐个解释）",
      "🔧 工具与技术 Tools": "- **工具名**：原理+怎么用+适用场景\n...（逐个解释，每个工具都要展开）",
      "📤 输出 Outputs": "- **输出名**：含义+后续用途\n...（逐个解释）",
      "🔗 与其他过程的相互作用": "本过程与前后过程的衔接关系...",
      "✂️ 裁剪考虑": "预测型/适应型/混合型差异...",
      "💼 实践案例": "一个简短的应用示例..."
    },
    "keyConcepts": "关键术语——（要点式）",
    "examTips": "考试重点/常见陷阱——（要点式）"
  }
}
```

## 各字段字数参考

| 字段 | 目标字数 |
|---|---|
| overview | 400-600 |
| details 每个条目 | 300-600（过程节点6条，合计约2000-3000） |
| keyConcepts | 300-500 |
| examTips | 300-500 |
| **合计** | **3000-5000** |

- [ ] 使用要点式 `- **术语**：解释` 格式
- [ ] 含 examTips
- [ ] 术语规范，无编造
